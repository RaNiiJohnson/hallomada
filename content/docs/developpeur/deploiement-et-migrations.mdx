## L'ordre à respecter

<Steps>
<Step title="Récupérer la branche">
```bash
git fetch origin
git checkout ccr-0c8eef51-463xld
pnpm install
```
`pnpm install` génère aussi les fichiers de cette documentation (`.source`).
</Step>
<Step title="Déploiement de développement">
Dans un premier terminal, laissé ouvert : `npx convex dev`. Il envoie le schéma mis à jour et régénère `convex/_generated/`.
</Step>
<Step title="Migrations, sur le développement">
Dans un deuxième terminal, **dans cet ordre** :
```bash
npx convex run aggregates:run '{"fn": "bump:backfillListedAtListings"}'
npx convex run aggregates:run '{"fn": "bump:backfillListedAtJobs"}'
npx convex run founders:rebuildFounders
```
Les deux premières remettent les anciennes annonces et offres à leur place dans les listes. La troisième recalcule les badges fondateur avec les nouvelles règles (les 100 premières annonces ou offres validées) et garde les badges donnés à la main. Toutes peuvent être relancées sans risque.
</Step>
<Step title="Tester">
Suivez la page [À vérifier](/admin/docs/a-verifier).
</Step>
<Step title="Production">
Déployez le backend (`npx convex deploy`), puis relancez les mêmes commandes avec `--prod`, par exemple `npx convex run --prod founders:rebuildFounders`.
</Step>
</Steps>

<Callout type="warning" title="Erreur « Can't find function »">
Le code n'est pas encore déployé sur ce déploiement. Déployez d'abord, puis relancez la commande.
</Callout>

<Callout type="info" title="Windows (PowerShell)">
Les guillemets s'écrivent autrement : `npx convex run aggregates:run '{\"fn\": \"bump:backfillListedAtListings\"}'`
</Callout>
